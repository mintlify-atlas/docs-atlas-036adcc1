Every game in the `offline/` directory is a single, fully self-contained HTML file. All assets — JavaScript, CSS, images, audio samples, fonts, and sprite sheets — are encoded inline as data URIs or embedded `<script>` and `<style>` blocks. Nothing is loaded from an external server at runtime. This means you can copy any individual file to a USB drive, a school Chromebook's Downloads folder, or an air-gapped device, and it will run exactly as intended in any modern browser.

## How Offline Files Work

<Steps>
  <Step title="All assets are inlined">
    During the creation process for each game, every external resource is fetched and re-encoded as a Base64 data URI or pasted directly into the HTML. The result is a single `.html` or `.htm` file that carries everything it needs.
  </Step>
  <Step title="No server or build step required">
    Because there is no server-side rendering and no asset manifest to resolve, the browser loads the entire game from one file. There is no `package.json`, no bundler, and no backend — just a file and a browser.
  </Step>
  <Step title="Compatible with any modern browser">
    The files target standard HTML5 APIs. They work in Chrome, Firefox, Edge, and Chromium-based browsers. Chromebooks running ChromeOS handle them natively.
  </Step>
</Steps>

## Opening a Game

You have two ways to play any offline game:

<Tabs>
  <Tab title="Directly in your browser">
    Double-click the `.html` file in your file manager or drag it into an open browser tab. The browser opens the file using the `file://` protocol and the game starts immediately — no hub, no web server, no internet needed.

    ```
    # Example: open slope directly (macOS / Linux)
    open offline/slope.html

    # Example: open on Windows (run from the repo directory)
    start offline\slope.html
    ```
  </Tab>
  <Tab title="Through the hub (index.html)">
    Open `index.html` in your browser, wait for the games library to load, then click any tile. The hub wraps the game in an iframe so you get the full toolbar experience — back/forward navigation, favorites, tab management, and the address bar.

    If the library does not load automatically, click **Choose games folder** and select the `offline/` folder. The hub reads the file list locally using the File System Access API and does not upload anything.
  </Tab>
</Tabs>

## A Note on File Sizes

Because every asset is inlined, individual game files are intentionally larger than typical web pages. A simple puzzle game might be a few hundred kilobytes; a game with audio tracks or large sprite sheets can reach several megabytes. This is expected behavior and is the direct cost of true offline portability — the entire game lives in one file.

<Warning>
  Some browsers impose a file size limit when opening local files via `file://`. If a very large game file fails to load, try opening it through a local web server or through `index.html` using the folder picker, which uses the File System Access API and avoids that limitation.
</Warning>

<Tip>
  If you only want to play a handful of games without downloading the entire repository, use `single-file.html` (v1.4.3.1). It lets you load individual offline HTML game files via a drag-and-drop interface and supports opening `.zip` archives through JSZip — no need to clone the full repo.
</Tip>
